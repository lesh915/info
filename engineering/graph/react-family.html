AGENT REASONING PATTERNS

ReAct 이후, 에이전트는 생각하는 순서를 바꾸기 시작했다

2022년 제안된 ReAct(Reason + Act)는 LLM이 한 스텝마다 생각하고(Thought), 행동하고(Action), 관찰한(Observation) 뒤 다시 생각하는 순환 구조로 도구 사용 에이전트의 기본형이 되었다. 하지만 스텝마다 LLM을 호출하는 구조는 토큰 비용과 지연시간이 단계 수에 비례해 늘어나고, 한 스텝의 실수가 다음 스텝으로 그대로 전파되며, 전체 목표를 조망하지 못한 채 매번 다음 한 걸음만 결정한다는 한계를 가진다. 이후 등장한 변형들은 이 세 가지 문제 — 비용, 오류 전파, 근시안적 계획 — 중 하나 이상을 겨냥해 설계되었다. 이 문서는 대표적인 네 가지 변형인 Plan-and-Execute, ReWOO, Reflexion과 더불어 이후 등장한 LATS 등을 원 논문을 기준으로 정리한다.

BASELINE · 2022

ReAct — 추론과 행동을 한 스텝씩 엮는다

Yao et al., 2022 · "ReAct: Synergizing Reasoning and Acting in Language Models" (ICLR 2023)

Thought다음에 뭘 할지 추론
Action도구 호출
Observation결과 관찰
↺ 목표를 달성하거나 최대 스텝에 도달할 때까지, 매번 LLM을 새로 호출하며 반복

이후 모든 변형이 비교 기준으로 삼는 원형이다. 매 스텝의 관찰 결과가 즉시 다음 추론에 반영되므로 예상 밖 상황에 유연하게 대응하고, 실제 도구 결과에 근거를 두어 환각을 줄인다. 다만 그 대가로 스텝 수만큼 LLM 호출이 늘어나고, 각 호출은 이전 대화 전체를 다시 읽어야 하므로 컨텍스트가 길어질수록 비용도 함께 커진다.

Plan-and-Execute

계획 수립과 실행을 분리하는 아키텍처 · LangChain 등 다수 프레임워크가 채택한 패턴

Planner전체 계획을 한 번에 수립
Step 1실행
Step 2실행
Step N실행
Answer최종 답 반환
↺ 결과가 계획과 어긋나면 Replanner가 남은 단계를 다시 세운다

강력한(비싼) 모델이 목표를 보고 순서가 있는 단계 목록을 한 번에 만들고, 이후 각 단계는 더 가볍고 저렴한 모델이나 실행기가 순서대로 수행한다. ReAct가 매 스텝 "다음엔 뭘 하지"를 다시 고민하는 것과 달리, Plan-and-Execute는 전체 목표를 먼저 조망한 뒤 실행에 들어가므로 단계 누락이 적고 계획 자체를 사람이 검토·승인하기도 쉽다. 실행 중 예상과 다른 결과가 나오면 별도의 Replanner가 남은 계획만 다시 세우는 형태로 최소한의 적응력을 확보하는 구현이 일반적이다.

LLM 호출 패턴

계획 1회 + 단계별

계획 시점

사전에 전체 수립

중간 적응력

중간 (재계획 시)

대표 사용처

보험 청구, 정형 보고서

장점

  • 전체 목표를 먼저 조망해 단계 누락과 방향 이탈을 줄인다.
  • 계획(비싼 모델)과 실행(저렴한 모델)을 분리해 비용을 낮출 수 있다.
  • 계획이 사람이 읽을 수 있는 형태로 나오므로 실행 전 검토·승인이 쉽다.

한계

  • 예상 밖 상황에는 경직적이다 — 플래너가 미리 상정하지 못한 변수에 약하다.
  • 재계획 로직이 없으면 한 단계의 실패가 그대로 전체 실패로 이어진다.
  • 플래너·실행자·(선택적) 리플래너로 아키텍처 복잡도가 ReAct보다 높다.

추론과 관찰의 분리 (토큰 비용 절감)

ReWOO — Reasoning WithOut Observation

Xu, Zhao et al., 2023 · "ReWOO: Decoupling Reasoning from Observations for Efficient Augmented Language Models"

Planner변수(#E1,#E2…)를 포함한 전체 계획을 1회 생성
Worker → #E1
Worker → #E2
Worker → #E3
Solver계획+증거를 종합해 답 생성
Worker는 LLM 호출 없이 병렬로 도구만 실행 — 전체 LLM 호출은 단 2회

ReAct는 도구 실행 결과(Observation)를 매번 LLM 컨텍스트에 다시 넣기 때문에 프롬프트가 스텝마다 길어진다. ReWOO는 이 관찰 값을 #E1, #E2 같은 변수 자리표시자로 남겨두고, Planner가 필요한 추론과 도구 호출 계획 전체를 한 번의 LLM 호출로 미리 완성한다. Worker들은 이 계획에 따라 LLM 없이 도구만 실행해 변수 값을 채우며, 서로 의존하지 않는 호출은 병렬로 처리할 수 있다. 마지막으로 Solver가 원래 계획과 채워진 증거를 한 번에 읽고 최종 답을 합성한다. 저자들은 멀티홉 QA 벤치마크에서 ReAct 대비 약 5배의 토큰 효율을 보고했다.

LLM 호출 패턴

고정 2회

계획 시점

사전 1회, 변수로 위임

중간 적응력

낮음 (계획 고정)

대표 사용처

멀티홉 QA, 병렬 조회

장점

  • LLM 호출이 2회로 고정되어 네 패턴 중 토큰·비용 효율이 가장 높다.
  • 독립적인 도구 호출을 병렬 실행해 지연시간을 줄인다.
  • Worker 하나가 실패해도 전체 파이프라인이 즉시 멈추지 않는다.

한계

  • 실행 중 적응이 전혀 없다 — 계획은 첫 LLM 호출 이후 고정된다.
  • 변수 간 의존 관계가 예상과 다르게 흘러가면 체인이 그대로 깨진다.
  • 결과를 어느 정도 예측할 수 있는 정형화된 과제에 적합하고, 탐색적 과제엔 약하다.

실패 후 자기 비평을 메모리에 저장

Reflexion — 말로 하는 강화학습

Shinn et al., 2023 (NeurIPS) · "Reflexion: Language Agents with Verbal Reinforcement Learning"

Actor과제 시도
Evaluator결과 채점
Self-Reflection실패 원인을 언어로 서술
Memory반성문 저장
↺ 다음 시도의 Actor는 저장된 반성문을 함께 참고 — 성공하거나 최대 시도 횟수까지 반복

가중치를 업데이트하는 대신, 시도 결과에 대한 언어적 피드백을 에피소드 메모리에 쌓아 다음 시도의 컨텍스트로 활용한다는 점이 핵심이다. Actor가 과제를 시도하면(ReAct 등 다른 패턴을 그대로 써도 된다) Evaluator가 성공·실패를 판정하고, 실패 시 Self-Reflection 모듈이 "왜 실패했는지"를 자연어 문장으로 남긴다. 이 반성문이 메모리 버퍼에 쌓이고, 다음 시도에서 Actor는 같은 실수를 반복하지 않도록 이 메모리를 함께 참고한다. 단위 테스트 통과 여부처럼 채점 기준이 명확한 과제에서 특히 효과가 크며, 논문은 HumanEval에서 pass@1 91%를 보고했다(같은 논문 기준 GPT-4 단독 80% 대비).

시도 횟수에 비례

계획 시점

시도마다 갱신

중간 적응력

세션 내 유일한 "학습"

대표 사용처

테스트 있는 코드 생성

장점

  • ReAct·Plan-and-Execute 등 다른 패턴 위에 얹는 오버레이 방식으로 결합할 수 있다.
  • 채점 기준이 명확한 과제(테스트, 정답 일치)에서 성능 향상 폭이 크다.
  • 실패 이유가 사람이 읽을 수 있는 자연어로 남아 디버깅에 유용하다.

한계

  • 재시도할 때마다 LLM 호출과 비용이 그대로 배로 늘어난다.
  • 자기평가 품질이 반성의 품질을 좌우한다 — 평가자가 오류를 못 짚으면 무용하다.
  • 같은 모델이 결과와 비평을 함께 생성하면 스스로의 맹점을 강화할 수 있다는 지적도 있다.

그 외 주목할 변형 — 탐색으로 확장

LATS와 그 밖의 흐름

Zhou et al., 2023–2024 (ICML) · "Language Agent Tree Search Unifies Reasoning, Acting, and Planning"

State현재까지의 궤적
후보 행동 A
후보 행동 B
후보 행동 C
선택(UCT) → 확장 → 평가 → 시뮬레이션 → 역전파 → 반성, 6단계를 반복하며 트리를 키운다

LATS(Language Agent Tree Search)는 ReAct가 하나의 궤적만 따라가다 한번 잘못 들어서면 되돌아오지 못한다는 한계를, 몬테카를로 트리 탐색(MCTS)으로 보완한다. 매 단계에서 여러 행동 후보를 샘플링해 트리를 확장하고, 언어 모델의 평가 점수와 자기일관성(self-consistency)을 함께 반영한 값 함수로 유망한 경로를 고르며, 실패한 경로에서는 Reflexion처럼 언어적 반성을 남겨 이후 탐색에 활용한다. 논문은 HotPotQA에서 ReAct 대비 약 2배의 정확도(0.63 vs 0.32), HumanEval에서 GPT-4 기준 pass@1 92.7%를 보고했다 — 다만 여러 후보 경로를 탐색하는 만큼 LLM 호출과 비용도 함께 크게 늘어난다.

더 살펴볼 만한 갈래. ADaPT(As-Needed Decomposition and Planning)는 실행 중 난이도를 판단해 필요한 하위 과제만 그때그때 더 쪼개는 "필요 시 분해" 접근을, Self-Ask는 복잡한 질문을 스스로 후속 질문으로 나눠가며 답하는 프롬프팅 패턴을 제안한다. 두 흐름 모두 "계획을 언제, 얼마나 세밀하게 세울 것인가"라는 같은 질문에 대한 또 다른 답이다.

선택 가이드

어떤 상황에 어떤 패턴을

매 순간 새로운 정보가 필요하다면

단계마다 관찰 결과가 다음 판단을 바꾸는 탐색적 과제에는 여전히 ReAct가 기본값이다.

과정이 반복되고 사람이 검토해야 한다면

절차가 어느 정도 정해져 있고 실행 전 계획을 승인받아야 한다면 Plan-and-Execute가 맞다.

토큰 비용이 가장 큰 제약이라면

독립적인 조회를 병렬로 처리할 수 있는 정형 과제라면 ReWOO로 호출 수를 2회까지 줄인다.

채점 기준이 명확한 반복 개선 과제라면

테스트·정답 일치처럼 성공을 자동으로 판별할 수 있다면 Reflexion을 다른 패턴 위에 얹는다.

정확도가 최우선이고 비용에 여유가 있다면

되돌아갈 수 있는 탐색이 필요한 고난도 과제라면 LATS처럼 트리 탐색을 곁들인다.

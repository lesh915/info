AGENT REASONING PATTERNS · PART 2

분해, 코드, 탐색 — ReAct 밖으로 더 뻗어나간 갈래들

앞선 문서(ReAct 패밀리)가 Plan-and-Execute, ReWOO, Reflexion, LATS처럼 "계획을 언제 세우는가"에 집중했다면, 이 문서는 그와는 다른 세 축을 겨냥한 변형들을 정리한다. 언제 문제를 쪼갤지 (Self-Ask, ADaPT), 행동을 어떤 형식으로 표현할지(CodeAct), 궤적을 얼마나 넓게 탐색할지(Tree/Graph of Thoughts)와, 지식을 어떻게 축적할지(Voyager)다. 마지막 절에서는 이 갈래들이 2025–2026년 실제 프로덕션 에이전트에 어떻게 녹아들었는지 최신 동향을 짚는다.

질문을 스스로 쪼개기 · 2022

Self-Ask

Press et al., 2022 · "Measuring and Narrowing the Compositionality Gap in Language Models"

Question원래 질문
Follow-up?후속 질문이 필요한가
Follow-up스스로 후속 질문 생성 → 답변
Final Answer후속 답들을 종합
↺ "Follow-up 필요 없음"이 나올 때까지 후속 질문 → 답변을 반복

저자들은 모델이 단일 사실 질문(single-hop)은 잘 맞히면서도, 그 사실들을 엮어야 하는 다중 홉(multi-hop) 질문에는 약하다는 구성성 격차(compositionality gap)를 지적한다 — 모델이 커질수록 단일 질문 성능은 빠르게 좋아지지만 다중 홉 성능은 그만큼 따라오지 못한다는 것이다. Self-Ask는 Chain-of-Thought에 "지금 후속 질문이 필요한가?"라는 명시적 체크포인트를 끼워 넣어, 모델이 스스로 하위 질문을 만들고 답한 뒤 최종 답을 조립하도록 강제한다. 이 구조가 정형화되어 있기 때문에 후속 질문에 대한 답을 모델 스스로 추측하는 대신 검색 엔진 호출로 대체하기도 쉽다 — ReAct보다 먼저 나온, "질문 분해"만으로 도구 결합의 길을 튼 프롬프팅 기법이다.

ADaPT — As-Needed Decomposition and Planning

Prasad, Koller et al., 2023 · "ADaPT: As-Needed Decomposition and Planning with Language Models" (NAACL 2024 Findings)

Task과제 실행 시도
성공? 실행기 역량 안에 있는가
성공 → 종료
실패 → 하위 과제로 재귀 분해
↺ 각 하위 과제에도 같은 판단을 재귀적으로 적용 — 실행기가 감당할 수 있을 때까지

Plan-and-Execute는 시작 전에 전체를 한 번에 쪼개고, ReAct는 아예 쪼개지 않은 채 매 스텝을 즉흥적으로 결정한다. ADaPT는 그 중간을 택한다 — 우선 과제를 통째로 실행해보고, 모델이 실제로 실패했을 때만 그 과제를 더 작은 하위 과제들로 재귀적으로 쪼갠다. 분해 여부와 깊이가 과제의 난이도, 그리고 그 순간 실행기 모델의 역량에 맞춰 동적으로 정해지는 셈이다. ALFWorld에서 성공률 28.3%p, WebShop에서 27%p, 저자들이 새로 만든 합성 과제 벤치마크 TextCraft에서 33%p의 향상을 보고했으며, 특히 여러 단계를 거치는 다층 분해가 성능에 결정적이었다고 밝힌다.

행동 자체를 코드로 · 2024

CodeAct

Wang et al., 2024 (ICML) · "Executable Code Actions Elicit Better LLM Agents"

Thought다음 행동 추론
Action = Code파이썬 코드로 행동 작성
Interpreter코드 실행 (반복문·조건문·도구 조합 가능)
Observation실행 결과 관찰
↺ ReAct와 같은 루프지만, Action 슬롯이 JSON/텍스트가 아니라 실행 가능한 코드

ReAct·Plan-and-Execute·ReWOO 모두 "행동을 어떻게 표현할지"는 대개 정해진 JSON이나 자연어 형식에 맡겨 왔다. CodeAct는 이 형식 자체를 실행 가능한 파이썬 코드로 통일하자고 제안한다 — 미리 정의된 액션 목록에 갇히지 않고, 반복문·조건문으로 여러 도구를 자유롭게 조합하거나 새 관찰에 따라 이전 행동을 그 자리에서 수정할 수 있다. 17개 모델을 API-Bank 등에서 평가해 기존 형식 대비 최대 20%p 높은 성공률을 보였고, 저자들은 이 방식으로 학습한 CodeActInstruct 데이터셋과 Llama2/Mistral 기반의 CodeActAgent도 함께 공개했다.

Tree of Thoughts · Graph of Thoughts

Yao et al., 2023 · "Tree of Thoughts: Deliberate Problem Solving with Large Language Models" / Besta et al., 2023 · "Graph of Thoughts"

Thought 0부분 풀이 상태
후보 사고 A
후보 사고 B
후보 사고 C
각 후보를 모델 스스로 평가(voting/scoring) → 유망한 가지만 BFS/DFS로 확장, GoT는 가지 간 병합도 허용

LATS가 몬테카를로 트리 탐색을 도구를 쓰는 에이전트에 적용한 것이라면, 그 개념적 뿌리는 순수 추론 과제(퍼즐, 수학, 창작 글쓰기)에 트리 탐색을 적용한 Tree of Thoughts다. ReAct의 단일 직선 궤적과 달리, 매 단계에서 여러 "사고(thought)" 후보를 생성하고 모델 스스로 각 후보의 유망함을 평가한 뒤 너비/깊이 우선 탐색으로 가지를 넓혀간다. Graph of Thoughts는 이 구조를 트리에서 임의의 그래프로 일반화해, 서로 다른 가지에서 나온 여러 사고를 하나로 병합하거나 다시 피드백 루프에 넣는 것까지 허용한다 — "생각을 한 방향으로만 뻗을 필요는 없다"는 관점의 확장이다.

Voyager

Wang et al., 2023 · "Voyager: An Open-Ended Embodied Agent with Large Language Models"

Curriculum다음 목표를 자동 제안
Code Action코드로 행동 시도
Self-Verify성공 여부 스스로 검증
Skill Library성공한 코드를 재사용 가능한 기술로 저장
↺ 저장된 기술은 다음 목표를 풀 때 그대로 불러와 조합 — 세션이 끝나도 남는 영구 메모리

Reflexion의 메모리가 "이번 시도가 왜 실패했는지"를 담는 임시 반성문이라면, Voyager의 메모리는 여기서 한 걸음 더 나아가 성공한 행동 자체를 영구적인 기술(skill)로 남긴다. 마인크래프트 환경에서 자동 커리큘럼이 다음으로 배울 만한 목표를 스스로 제안하면, 에이전트는 코드로 행동을 시도하고(CodeAct와 유사한 코드-행동 방식), 성공 여부를 스스로 검증한 뒤 성공한 코드를 스킬 라이브러리에 저장해 이후 과제에서 다시 조합해 쓴다. 외부 개입 없이 스스로 목표를 정하고 능력을 넓혀간다는 점에서, 세션 단위로 끝나는 다른 패턴들과 달리 평생학습(lifelong learning) 관점을 에이전트 루프 안으로 끌어들인 초기 사례로 꼽힌다.

2025–2026 최근 동향

이 패턴들은 지금 어떻게 조합되고 있나

2022–2024년의 변형들이 "어떤 패턴을 고를 것인가"의 문제였다면, 2025–2026년의 실제 시스템들은 이 패턴들의 아이디어를 부품처럼 조합해 하나의 스택으로 쌓는 쪽으로 수렴하고 있다.

Test-Time Reasoning

추론이 루프 안으로 내재화된다

OpenAI o-시리즈, DeepSeek-R1, Claude의 확장 사고(extended thinking)처럼 모델이 답을 내기 전에 내부적으로 여러 차례 "숙고 토큰"을 생성한다. ReAct의 Thought 스텝이 프롬프트 바깥에서 오케스트레이션하던 추론을, 이제 모델 자신이 추론 시점에 직접 수행한다 — 외부 루프와 모델 내부 추론의 경계가 흐려지는 추세다.

Tool-Integrated RL

도구 사용 자체를 강화학습으로 훈련

ReTool(2025) 같은 연구는 "언제, 어떻게 도구를 부를지"를 프롬프트 설계가 아니라 강화학습으로 모델에 학습시켜, 추론과 코드 실행(인터프리터 호출)을 모델이 자연스럽게 번갈아 쓰도록 만든다. CodeAct가 제안한 "행동=코드"를 프롬프팅이 아닌 학습 단계에서 내재화한 흐름으로 볼 수 있다.

Process Reward

최종 답이 아니라 중간 과정에 보상

결과만 채점하던 Reflexion식 피드백에서 한 걸음 더 나아가, 추론 과정의 각 단계에 보상 신호를 줘 모델이 진행 중간에 스스로를 점검(self-check)하도록 학습시키는 접근이 확산되고 있다.

Protocol Standardization

도구·에이전트 연결의 표준화

Anthropic의 MCP(Model Context Protocol)는 에이전트와 도구·데이터 연결 방식을, Google의 A2A(Agent-to-Agent)는 서로 다른 플랫폼의 에이전트 간 통신 방식을 표준화한다. ReWOO의 Worker나 CodeAct의 도구 호출처럼 개별 패턴 안에 감춰져 있던 "도구를 어떻게 부를지"가 프레임워크 밖 공통 규격으로 분리되는 중이다.

Multi-Agent Orchestration

하나의 거대한 에이전트 대신 여러 전문 에이전트

도구 50개를 가진 에이전트 하나보다, 도구 10개씩을 가진 전문 에이전트 5개를 오케스트레이터가 조율하는 구조로 무게중심이 옮겨가고 있다. Plan-and-Execute의 플래너/실행자 분리가 조직 단위로 확장된 형태에 가깝다.

Persistent Memory

메모리가 세션을 넘어 영구화된다

장기 실행 에이전트는 대화 기록을 컨텍스트 창에 쌓는 대신 벡터DB나 메모리 파일로 오프로딩한다. Reflexion의 에피소드 메모리, Voyager의 스킬 라이브러리가 프로토타입이던 개념이 이제 인프라 계층의 기본 구성요소가 되는 흐름이다.

종합하면. 2022–2024년의 변형들은 대개 "이 패턴 아니면 저 패턴" 식의 단일 선택지로 논문에 등장했다. 2025–2026년의 실무 스택은 오히려 이들을 재료로 삼아 — 추론 모델의 내재화된 숙고 + 강화학습으로 다듬은 도구 사용 + 단계별 보상 + 표준 프로토콜로 연결된 여러 전문 에이전트 + 영구 메모리 — 하나의 시스템 안에 겹겹이 쌓는 방향으로 수렴하고 있다.
